# Robustness of Interpretable Tabular Classifiers under Random Feature Missingness

Reproduction code for the manuscript of the same title (prepared for submission to the
Vietnam Journal of Computer Science; this repository contains code, results
and figures only, not the manuscript itself).

## What this repository is — and is not

- It contains every experiment script behind the manuscript's tables:
  `exp1.py`–`exp9_ctrack.py`, plus `make_figures.py` for Figures 1–3. Figures 4–5 (MAR curves, coefficient forest plot) are generated from `results7_mar_paired_coef.json` and are included in `figures/`.
- It contains the committed result files in `results/` and the committed
  figures in `figures/` (SVG only in this snapshot; the PDF and 300 dpi PNG
  versions are regenerated by `make_figures.py`). Running the scripts again
  should reproduce those files, except for fit-time values (see below).
- It does **not** prove the conclusions are correct. It proves only that
  the stated protocol, run in the stated environment, produces the stated
  numbers. That distinction is kept in the manuscript as well.

## Environment

- Python 3.12
- Install: `pip install -r requirements.txt`
- Versions used for the committed results: scikit-learn 1.9.1,
  numpy 2.5.4, pandas 3.1.0, scipy 1.18.1, matplotlib 3.6.3
  (matplotlib is needed only for `make_figures.py`).

## Run order

Run from the repository root, in this order. Each `exp*.py` writes its
result file to the **current working directory**, not to `results/`,
so run the scripts from a clean output directory if you do not want to
overwrite the committed files:

```bash
python exp1.py   # -> results.json
python exp2.py   # -> results2.json
python exp2b_repeated.py  # -> results2b.json
python exp3_candidates.py  # -> results3.json
python exp4_supplement.py  # -> results4.json
python exp5_verify.py  # -> results5_verify.json
python exp6_aux_svm.py  # -> results6_aux_svm.json
python exp7_mar_paired_coef.py  # -> results7_mar_paired_coef.json
python exp8_btrack.py  # -> results8_btrack.json
python exp9_ctrack.py  # -> results9_ctrack.json
```

Then, with the result files available (either freshly generated in the
current directory or the committed files in `results/`), regenerate
the figures:

```bash
python make_figures.py  # reads results/, writes figures/ (SVG, PDF, 300 dpi PNG)
```

## How to verify a rerun

Compare each freshly generated result file with the committed file in
`results/` (for example with `diff` or a JSON comparison). The committed
reruns matched exactly for every scientific value. The only expected
differences are:

- Fit times in `results2.json` (`fit_time_fold0_sec`): these are machine
  timings and will vary. The manuscript reports them as indicative,
  single-fold timings only.
- Nothing else should differ. A difference in any AUC, accuracy, drop,
  paired-test, MAR, or coefficient value is a real discrepancy — please
  report it with the Python and scikit-learn versions used.

## Protocol (fixed, no tuning)

- Stratified 5-fold cross-validation, `random_state=42` throughout.
- Missingness is imposed on the **test fold only**. Imputers, scalers and
  feature selectors are fitted on the training fold only.
- MCAR masks: seed `1000 + fold`. Grouped masks: seed `2000 + fold`.
  MAR masks: seeds `3000 + fold` (MAR+) and `4000 + fold` (MAR-).
- Models use default or near-default settings as written in the scripts;
  no hyperparameter search was performed. This is a stated limitation
  of the manuscript, not an oversight in the code.

## Data sources

- WDBC, Wine, Digits: scikit-learn built-in datasets (`load_breast_cancer`,
  `load_wine`, `load_digits`). WDBC labels are flipped in the scripts so
  that 1 = malignant.
- Ionosphere, Heart Cleveland: UCI Machine Learning Repository downloads
  at run time in `exp3.py`–`exp7.py`. Because live UCI links can change
  (the Pima UCI link already returned 404 during this work), local copies
  of the two files actually used in the main text are vendored in `data/`
  with their source URLs and SHA-256 hashes in `data/README.md`.
  Pima (excluded from the main text) is obtained via OpenML `data_id=37`
  in `exp5_verify.py`.
- No patient data, no private data and no paid service were used.
  No credentials, tokens or personal information are in this repository.
